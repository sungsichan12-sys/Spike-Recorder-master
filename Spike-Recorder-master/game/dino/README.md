# Signal Dino 3D — 4 stages

`G` → **Signal Dino 3D**. 일반 피크와 강한 피크로 진행하며, 3단계에 마법, 4단계에 황금 레이저 기준선이 추가됩니다.

## 독립 게임 모듈

게임 전체를 `game/dino/`에 분리했습니다. `DinoGame.cpp`와 `DinoGame.h`는 호스트 연결·입력·화면, `DinoRunner.h`는 게임 규칙, `DinoPeak.h`는 피크 분류, `DinoScene.h`와 `DemonKingScene.h`는 모델과 장면을 담당합니다. `game.ini`가 `DinoGame.dll`을 지정하며, 최상위 실행 BAT가 변경된 소스를 빌드합니다. 폴더를 추가·제거하면 G 목록에도 반영됩니다. 공용 3D 도구와 플러그인 인터페이스는 `src/games/`에 남습니다.

## 1. 사막 — 여의주 5개

장애물 위의 황금 여의주를 점프로 모읍니다. **진화 조건을 3개에서 5개로 상향**했습니다. 일반/긴 점프 모두 수집할 수 있으며, 놓치면 다음 장애물에 다시 등장합니다.

다섯 번째 여의주를 모으면 용으로 진화합니다. 약 3.6초 동안 세 겹의 충격파, 날개 끝 화염 궤적, 불꽃 소용돌이, 떨어지는 금빛 불씨와 함께 몸을 세워 상승합니다. 카메라가 용을 중심으로 돌며 따라 올라가고, 구름이 갈라진 뒤 화면이 밝아지며 2스테이지로 전환합니다. 연출 중에는 입력·충돌·장애물 생성을 중지합니다.

## 2. 하늘 — 수정 8개 제거

구름과 공중 유적 사이에서 비행합니다. **불뿜기로 수정 장애물 8개를 파괴하면** 폭풍 속 3스테이지로 이동합니다. 날갯짓으로 넘는 것은 생존에 도움이 되지만 파괴 수에는 포함되지 않습니다.

기본 고도는 자동으로 유지됩니다. 일반 피크로 위로 날갯짓하고, 강한 피크로 불을 뿜습니다. 불뿜기는 1초 간격으로 사용할 수 있습니다. 새 스테이지에 들어오면 첫 공격 전 준비 시간이 있습니다.

비행 중에는 무릎을 배 쪽으로 접고 발목과 발톱을 뒤로 말아 올립니다. 관절은 날갯짓보다 약간 늦게 움직이며, 첫 상승 중에는 지상 자세에서 비행 자세로 부드럽게 전환합니다.

수정 8개를 파괴하면 마법 고리와 빛 입자가 몸을 감싸며 **메가 진화**합니다. 뿔과 날개 끝이 자라고 청색 장갑과 발광 날개 무늬가 생깁니다. 진화가 끝나면 3단계와 함께 마법을 사용할 수 있습니다.

## 3. 폭풍 — 수호룡 보스전

수호룡의 체력은 **8칸**이며 위쪽 체력 막대에 표시됩니다.

- 다가오는 보랏빛 공격을 일반 피크로 넘거나 강한 피크의 불로 막습니다.
- 공격이 비는 틈에 불을 뿜으면 수호룡의 체력이 1칸 줄어듭니다.
- 한 번의 불은 보스에게 한 번만 피해를 줍니다. 다가오는 공격을 막은 불은 보스까지 관통하지 않습니다.
- **마법 피크 / M**: 용 앞에 이중 마법진을 열고 0.28초 충전 후 에너지 빔을 발사합니다. 빔은 앞으로 이동하며 경로의 공격을 제거하고 보스에게 한 번만 2칸 피해를 줍니다. 재사용 대기 시간은 3.5초입니다.
- 수호룡의 체력을 모두 줄이면 빛으로 변한 수호룡이 자신의 힘을 플레이어에게 전합니다. 5초 동안 힘의 흐름과 금빛 고리가 나타나고, 백금색 비늘·금빛 뿔·수염·날개 장식의 **신룡**으로 진화한 뒤 4단계로 이동합니다. 연출 중에는 충돌과 공격 입력이 잠깁니다.

## 4. 마왕성 — 최종 마왕전

붉은 하늘과 검은 성채 앞에서 왕관·뿔·갑옷·망토를 갖춘 마왕과 싸웁니다. 체력은 **20칸**입니다. 공격 전 붉은 마법진이 나타나며, 체력이 절반 이하가 되면 공격 간격이 2.1초에서 1.6초로 줄어듭니다. 일반 날갯짓·불뿜기·푸른 마법탄도 계속 사용할 수 있습니다.

마왕 모델은 `game/dino/DemonKingScene.h`에 분리했습니다. 굽은 뿔, 눈두덩과 턱, 겹쳐진 흉갑·견갑·정강이 갑옷, 손가락과 발톱, 구부러진 날개 뼈대와 막, 흔들리는 주름 망토, 불빛이 흐르는 대검으로 구성됩니다. 한 손을 든 비대칭 전투 자세를 사용하며, 공격 준비 시 손을 더 들어 올립니다. `tests/dino-demon-detail.png`는 같은 모델의 근접 미리보기입니다.

- 새 스킬 **태양 레이저**: 전방의 거대한 황금 마법진을 0.6초 동안 충전하고, 약 0.9초 동안 굵은 광선을 발사합니다.
- 한 번에 마왕 체력 **4칸**을 줄이고, 발사 중 경로의 공격을 지웁니다. 충전 중에는 무적이 아니므로 미리 사용하거나 공격을 피해야 합니다.
- 재사용 시간은 **6초**입니다. 마법탄과 레이저는 동시에 시전하지 않습니다.
- 마왕을 처치하면 **ALL 4 STAGES CLEAR!**가 나타납니다.
- 승리 직후 남은 입력으로 바로 재시작되지 않도록 1.8초 뒤부터 다시 시작할 수 있습니다.

충돌하면 실패합니다. 실패/클리어 후 재시작하면 1스테이지부터 진행하며, 최고 점수와 신호 휴식 기준은 유지됩니다.

## 조작

| 입력 | 1스테이지 | 2·3·4스테이지 |
|---|---|---|
| 일반 피크 / Space / 왼쪽 클릭 | 점프 | 위로 날갯짓 |
| 강한 피크 / ↑ / 오른쪽 클릭 | 긴 점프 | 불뿜기 |
| 마법 피크 / M | 사용 불가 | 3·4단계에서 에너지 빔 |
| 황금 피크 / L | 사용 불가 | 4단계에서 태양 레이저 |

강한 피크 기준은 일반 점프 기준의 1.8배입니다. 다음 동작 전에 힘을 빼거나 소리를 멈춰 입력을 분리합니다. 센서가 없으면 선택한 마이크 신호로 조작할 수 있습니다. `[` / `]`로 민감도를 조절하고 `Esc` / `GAME LIST`로 목록에 돌아갑니다.

마법 기준은 일반 기준의 **2.6배**이며, 3단계 오른쪽 그래프에 보라색 선과 재사용 시간이 나타납니다. 기준선을 넘은 뒤 최대 100ms 동안 피크를 모아 동작 하나를 선택하므로 강한 신호가 올라오는 도중 날갯짓이나 불뿜기로 먼저 소비되지 않습니다. 마법 대기 중 높은 피크는 불뿜기로 자동 대체되지 않습니다.

레이저는 일반 기준의 **3.4배** 신호로 사용하며, 4단계 그래프에 금색 선이 추가됩니다. 센서 피크 하나당 가장 높은 단계의 동작 하나만 실행합니다. 대기 중인 레이저 입력을 다른 공격으로 자동 대체하지 않습니다.

## 개발자 모드

게임 안에서 **F2**로 켜고 끕니다. 아래에 단축키와 무적 상태가 표시됩니다.

| 키 | 기능 |
|---|---|
| 1 / 2 / 3 / 4 | 해당 단계의 시작 상태로 즉시 이동 |
| E | 다음 진화 연출 시작. 3단계에서는 수호룡의 힘 전달과 신룡 진화를 재생. 4단계에서도 같은 연출 재생 |
| I | 무적 켜기/끄기 |
| C | 불뿜기·마법·레이저 대기 시간 초기화 |
| R | 첫 단계로 재시작 |
| M | 마법 발사 (3·4단계) |
| L | 황금 레이저 발사 (4단계) |

신규 기능 확인: **`F2 → 3 → E`**로 힘 전달과 신룡 진화, **`F2 → 4 → L`**로 마왕전의 황금 레이저를 확인합니다.

기존 기능 확인: `F2 → 2 → E`로 메가 진화를 보고, 진화 후 `M`으로 마법진과 빔을 확인합니다. `F2 → 3 → I`는 보스전 무적 테스트입니다. 이동·재시작 시 무적은 꺼집니다. 개발자 모드의 플레이는 PRACTICE로 표시되며 최고 기록에 반영하지 않습니다. 모드를 끈 현재 판도 연습 판으로 유지되고, 다음 재시작부터 정상 기록을 사용합니다.

## 검증과 미리보기

`tests/dino_3d_tests.cpp`: 5개 수집, 세 번의 스테이지 전환, 연출 중 보호, 비행·불뿜기, 보스 공격/피격/승리/재시작, 실제 규칙으로 1~4스테이지 완주, 마법 충전·이동·관통·단일 피해·승리, 개발자 모드의 상태/기록 분리, 신호 피크 판정, 화면 경계 등 **51개 회귀 검사** (수호룡 힘 전달·신룡 진화·마왕 분노·레이저 충전/지속/단일 피해/승리/실패·네 번째 피크·고밀도 곡선 모델의 자세 및 근거리 클리핑·공유 꼭짓점 렌더링 비교 포함).

`dino-bestow.png`는 수호룡의 힘 전달, `dino-demon.png`는 마왕전, `dino-solar-laser.png`는 황금 레이저 장면입니다.
`dino-magic-seal.png`와 `dino-magic-beam.png`는 마법진 충전과 빔 이동 장면입니다.
`tests/render_dino_cinematic.py`: `dino_3d_tests.exe --ascent-preview`가 내보낸 72개 실제 프레임을 `dino-cinematic.gif`로 만듭니다. 출력 폴더 `tests/dino-cinematic`이 먼저 있어야 합니다.

미리보기는 UI를 제외한 장면 렌더링입니다. 앱 창을 열거나 화면을 조작하지 않았으므로 실제 OpenGL 화면·실물 센서 플레이는 별도 확인이 필요합니다.

## 부드러운 그래픽

몸통과 꼬리는 곡선으로 보간하고, 생물·구름·뿔·갑옷은 꼭짓점 음영과 하늘 반사광을 사용합니다. 날개 막에는 곡면을, 사막에는 완만한 굴곡을 추가했습니다. 깊이 버퍼로 겹치는 표면을 픽셀별로 가려 면 조각이 끼어 보이는 현상을 줄입니다. 지원되는 그래픽 장치에서는 4배 멀티샘플링으로 윤곽을 다듬으며, 생성 실패 시 기본 OpenGL로 다시 시도합니다.

`src/games/ModelMesh.h`는 방향이 뒤집히지 않는 곡선 단면 이동, 회전 곡면, 속이 빈 둥근 테두리와 모서리를 다듬은 상자를 제공합니다. 공룡의 팔다리·발톱, 드래곤의 뿔·날개뼈·수염, 마왕의 팔과 뿔이 이를 사용합니다. 날개 끝선은 오목한 곡선으로, 막과 망토는 곡면 음영으로 연결합니다. 마왕 갑옷에는 안쪽 면·좁은 모서리·옆벽을 두어 두께를 표현합니다. 암벽의 불규칙한 윤곽은 스크롤 중에도 형태가 바뀌지 않으며, 유적 기둥의 받침과 주두·성탑·보의 모서리도 모델링했습니다.

`dino-character-detail.png`, `dino-dragon-detail.png`, `dino-divine-detail.png`, `dino-demon-detail.png`는 각 모델을 가까이 보는 오프라인 미리보기입니다.

## 고밀도 모델

머리·몸통의 원주는 16→32각, 제어 단면 사이의 보간은 2→3단계로 늘렸습니다. 큰 관절은 24×12 구면 단면, 날개막은 8단계 격자, 마왕 망토는 28×14 격자를 사용합니다. 뿔과 팔다리는 화면에서 충분히 크게 보이는 부분의 원주·길이 단면을 함께 늘립니다. 마왕 갑옷의 앞면은 볼록한 곡면을 세분화하며, 곡면을 정의하는 실제 위치도 보간합니다.

아래 값은 `tests/model_geometry_benchmark.cpp`의 동일한 카메라에서 측정한 가시 삼각형 수입니다. 뒷면 제거와 화면 경계 처리가 끝난 수치여서 모델 전체 원본의 삼각형 수와 다릅니다.

| 모델 | 이전 | 현재 |
|---|---:|---:|
| 공룡 | 2,344 | 6,760 |
| 드래곤 | 2,916 | 8,502 |
| 메가 드래곤 | 3,464 | 9,821 |
| 신룡 | 4,180 | 12,669 |
| 수호룡 | 2,916 | 8,502 |
| 마왕 | 5,323 | 15,304 |
| 드럼 세트 | 10,435 | 32,847 |

`Scene::indexedQuads`는 단면의 공유 꼭짓점마다 변환·조명·안개를 한 번만 계산합니다. 기존 면별 경로와 같은 클리핑·색·깊이를 내는지 회귀 검사합니다. 효과와 배경을 포함한 테스트 장면의 면 예산은 24,000개입니다. 벤치마크의 CPU 시간은 장면 생성 비용이며 앱의 실제 FPS 측정값이 아닙니다.

## 홈페이지 랭킹

승리 또는 게임 오버가 되면 한 번만 점수를 최상위 `server/outbox`에 저장합니다. 최상위 실행 BAT가 시작하는 클라우드 전송기가 Google Apps Script로 전송해 홈페이지에 표시합니다. 인터넷이 끊겨도 대기 기록은 보존되며, 개발자 연습 판과 녹화 파일 입력은 제외합니다. 설정은 최상위 `CLOUD_SETUP.md`를 참고합니다.

미리보기는 `tests/scene_raster.py`에서 실제 장면의 색과 역깊이를 보간합니다. 실사 텍스처나 물리 기반 재질을 사용하는 엔진으로 교체한 것은 아니며, 기존 절차적 3D 스타일에서 표면과 조명을 개선한 버전입니다.
